How Domain Swaps Destroyed Store History in Deep2K — And the Permanent "Same Store UUID + Domain Alias" Architecture

Whenever a .ca or .shop domain was suspended or rotated to .store / .com (32 times in October across Toronto, Winnipeg, Calgary, Vancouver, Steinbach, Hamilton, etc.), the team created a brand-new site row in Deep2K and deleted or abandoned the old row. Look at apps/api/src/routes/sites.ts (lines 177–194): deleting a site row executes DELETE FROM checkouts WHERE site_id = id, DELETE FROM events WHERE site_id = id, cascades deletes across journey_sessions and daily_stats, and sets UPDATE orders SET site_id = NULL, session_id = NULL, checkout_id = NULL — permanently orphaning every historical order into (unattributed) with no store!

1The Exact Code in new-deep2k That Destroyed Domain History

Look at apps/api/src/routes/sites.ts lines 27–33 and lines 177–194 in rosicjacob-sys/new-deep2k.

Bug #1: UpdateSiteBody (sites.ts:27–33) Forbids Renaming a Store's Domain!

Look at the schema for PATCH /api/sites/:id:

const UpdateSiteBody = z.object({
  endpointPath: z.string().startsWith('/').max(128).optional(),
  categoryId: z.string().uuid().optional().nullable(),
  shopifyDomain: z.string().max(253).optional().nullable(),
  checkoutDomain: z.string().max(253).optional().nullable(),
}).strict(); // <-- 'domain' IS NOT ALLOWED!

Because domain is missing from UpdateSiteBody, when torontopeptides.shop changed to torontopeptides.store, the admin could not rename the domain on the existing Toronto store! Instead, they clicked Add Site (creating a brand-new site_id UUID with 0 history and a different tracker script!).

Bug #2: deleteSite() (sites.ts:177–194) Wipes All Visits & Orphans Orders!

When someone deletes the old domain row (DELETE /api/sites/:id), here is what Deep2K runs:

async function deleteSite(id: string) {
  const kept = await tx.execute(sql`
    UPDATE orders
    SET site_id = NULL, checkout_id = NULL, session_id = NULL
    WHERE site_id = ${id} ...`);
  await tx.execute(sql`DELETE FROM checkouts WHERE site_id = ${id}`);
  await tx.execute(sql`DELETE FROM events WHERE site_id = ${id}`);
  const [row] = await tx.delete(sites).where(eq(sites.id, id));
}

Deleting the old domain row deletes every checkout, every session (CASCADE), every daily stat (CASCADE), and strips site_id and session_id off every paid order — turning real orders into storeless (unattributed) rows!

Bug #3: Even if you don't delete the old row, creating a second row splits the city into two stores and breaks the tracker!
When torontopeptides.store is created as a new site row:
  1. All Oct 1–19 visitors (Prev visitors in Deep2K) sit on torontopeptides.shop, so torontopeptides.store shows Prev visitors = 0 (see Section 4 of Deep2K!).
  2. The Shopify theme (xxx.myshopify.com) still has the old torontopeptides.shop script until someone manually re-pastes the new script — AND while the old script runs on the new domain, POST /api/sites/:id/handoff (integrations.ts:190) rejects every checkout handoff with 403 Storefront origin mismatch because originHost (torontopeptides.store) doesn't match site.domain (torontopeptides.shop)!

3Database Migration: site_domain_aliases (1 Store UUID = Unlimited Domains Over Time)

Add this append-only SQL migration (packages/db/migrations/0025_site_domain_aliases.sql) so a store keeps its site_id forever even if its domain changes 10 times.

Core Architectural Rule: A store in Deep2K represents a Shopify Store / City Franchise (site_id UUID), NOT a temporary domain name! When a domain changes (e.g., oshawapeptides.ca → oshawapeptides.store → oshawapeps.com):
  1. The store’s sites.id (UUID), sites.secret, and sites.endpoint_path NEVER CHANGE. That means you don't even have to re-paste the tracker script in Shopify theme.liquid when you change domains on the same Shopify store!
  2. The old domain is automatically saved into site_domain_aliases (domain, site_id, retired_at).
  3. Cloudflare KV keeps routing beacons from both the old domain AND the new domain to the exact same site_id, and POST /api/sites/:id/handoff accepts checkout handoffs from both the primary sites.domain AND any alias in site_domain_aliases!
-- packages/db/migrations/0025_site_domain_aliases.sql
CREATE TABLE IF NOT EXISTS site_domain_aliases (
  domain text PRIMARY KEY,
  site_id uuid NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  created_at timestamptz NOT NULL DEFAULT now(),
  retired_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS site_domain_aliases_site_idx ON site_domain_aliases(site_id);

-- Backfill existing primary domains into the alias lookup
INSERT INTO site_domain_aliases (domain, site_id)
SELECT lower(domain), id FROM sites
ON CONFLICT (domain) DO NOTHING;

4Two New Endpoints in apps/api/src/routes/sites.ts: rotate-domain & merge-into

4.1 POST /api/sites/:id/rotate-domain (In-Place Domain Swap With Zero Data Loss)

// Add to apps/api/src/routes/sites.ts
router.post('/sites/:id/rotate-domain', async (req: Request, res: Response) => {
  const id = req.params.id ?? '';
  const newDomain = normalizeDomain(String(req.body?.newDomain ?? ''));
  if (!newDomain) {
    res.status(400).json({ error: 'Valid newDomain required (e.g. monctonpeps.com)' });
    return;
  }

  const [site] = await db.select().from(sites).where(eq(sites.id, id));
  if (!site) { res.status(404).json({ error: 'Site not found' }); return; }
  const oldDomain = site.domain.toLowerCase();
  if (oldDomain === newDomain) { res.json({ ok: true, site }); return; }

  // If someone already created a separate new site row for newDomain,
  // automatically merge it into this site row instead of failing with 409!
  const [duplicateNewRow] = await db.select().from(sites).where(eq(sites.domain, newDomain));

  await db.transaction(async tx => {
    if (duplicateNewRow && duplicateNewRow.id !== site.id) {
      await mergeSiteData(tx, duplicateNewRow.id, site.id);
      await tx.delete(sites).where(eq(sites.id, duplicateNewRow.id));
    }
    await tx.execute(sql`
      INSERT INTO site_domain_aliases (domain, site_id, retired_at)
      VALUES (${oldDomain}, ${site.id}, now()), (${newDomain}, ${site.id}, now())
      ON CONFLICT (domain) DO UPDATE SET site_id = ${site.id}, retired_at = now()
    `);
    await tx.update(sites).set({
      domain: newDomain,
      firstPartySubdomain: site.firstPartySubdomain
        ? `${site.firstPartySubdomain.split('.')[0]}.${newDomain}`
        : null,
    }).where(eq(sites.id, site.id));
  });

  const endpointForWorker = resolveEndpointPath(site.endpointPath, env.CF_WORKER_URL);
  await pushSiteToKV(newDomain, { id: site.id, secret: site.secret, endpoint_path: endpointForWorker, backend_url: site.backendUrl }, null);
  await pushSiteToKV(oldDomain, { id: site.id, secret: site.secret, endpoint_path: endpointForWorker, backend_url: site.backendUrl }, null);

  invalidateSummaryCache();
  res.json({ ok: true, siteId: site.id, oldDomain, newDomain, message: 'Domain rotated in-place with 100% history preserved.' });
});

4.2 mergeSiteData() Helper & POST /api/sites/:targetId/merge-from/:sourceId

For the 32 stores where a second site row was already created (peptideschicago.com + chicagopeps.com, torontopeptides.shop + torontopeptides.store, etc.), this transaction moves 100% of historical visits, sessions, checkouts, orders, leads, and ad spend from sourceId into targetId before removing the duplicate row:

// Add to apps/api/src/routes/sites.ts
async function mergeSiteData(tx: Db, sourceId: string, targetId: string) {
  if (sourceId === targetId) return;
  const [src] = await tx.select().from(sites).where(eq(sites.id, sourceId));
  if (src) {
    await tx.execute(sql`
      INSERT INTO site_domain_aliases (domain, site_id, retired_at)
      VALUES (${src.domain.toLowerCase()}, ${targetId}, now())
      ON CONFLICT (domain) DO UPDATE SET site_id = ${targetId}
    `);
  }
  await tx.execute(sql`UPDATE events SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE journey_sessions SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE journey_events SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE checkouts SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE orders SET site_id = ${targetId}, updated_at = now() WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE leads SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE attributions SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE marketing_links SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`UPDATE marketing_spend SET site_id = ${targetId} WHERE site_id = ${sourceId}`);
  await tx.execute(sql`
    INSERT INTO daily_stats (site_id, date, pageviews, unique_visitors, countries, devices, top_paths, top_referrers, bounced_visitors)
    SELECT ${targetId}, date, pageviews, unique_visitors, countries, devices, top_paths, top_referrers, bounced_visitors
    FROM daily_stats WHERE site_id = ${sourceId}
    ON CONFLICT (site_id, date) DO UPDATE SET
      pageviews = daily_stats.pageviews + EXCLUDED.pageviews,
      unique_visitors = daily_stats.unique_visitors + EXCLUDED.unique_visitors,
      bounced_visitors = daily_stats.bounced_visitors + EXCLUDED.bounced_visitors
  `);
  await tx.execute(sql`DELETE FROM daily_stats WHERE site_id = ${sourceId}`);
}

5Patching Handoff & Portal Lookup to Accept Domain Aliases

Two small updates in apps/api/src/routes/integrations.ts so checkout handoffs and portal orders work across old and new domains.

// 1. In apps/api/src/routes/integrations.ts: update portalStore() (line 53)
async function portalStore(db: Db, event: { site_id?: string; store_domain?: string }): Promise<{ id: string; domain: string } | null> {
  if (event.site_id) {
    const site = await db.query.sites.findFirst({ where: eq(sites.id, event.site_id), columns: { id: true, domain: true } });
    if (site) return site;
  }
  const host = storeHost(event.store_domain);
  if (!host) return null;
  const rows = (await db.execute(sql`
    SELECT s.id, s.domain FROM sites s
    LEFT JOIN site_domain_aliases a ON a.site_id = s.id
    WHERE regexp_replace(lower(s.domain), '^www\\.', '') = ${host}
       OR regexp_replace(lower(s.shopify_domain), '^www\\.', '') = ${host}
       OR regexp_replace(lower(a.domain), '^www\\.', '') = ${host}
    GROUP BY s.id, s.domain
    LIMIT 2
  `)).rows as { id: string; domain: string }[];
  return rows.length === 1 ? rows[0]! : null;
}

6Retroactive SQL Rescue Script: Re-Attach Orphaned Orders & Merge City Duplicates

Run this SQL script once on Deep2K's PostgreSQL database to recover orders that lost their site_id when old .ca/.shop rows were deleted.

-- 1. Re-attach orphaned orders (where site_id was set to NULL by deleteSite)
UPDATE orders o
SET site_id = s.id, updated_at = now()
FROM sites s
WHERE o.site_id IS NULL
  AND (
    (o.external_order_id LIKE 'shopify:%' AND split_part(o.external_order_id, ':', 2) = lower(s.shopify_domain))
    OR (o.landing_url IS NOT NULL AND lower(regexp_replace(o.landing_url, '^https?://(www\.)?([^/?#]+).*$', '\2')) = lower(s.domain))
  );

-- 2. Re-attach orphaned orders where landing_url had the old .ca or .shop domain of the same city!
UPDATE orders o
SET site_id = s.id, updated_at = now()
FROM sites s
WHERE o.site_id IS NULL
  AND o.landing_url IS NOT NULL
  AND regexp_replace(split_part(lower(regexp_replace(o.landing_url, '^https?://(www\.)?([^/?#]+).*$', '\2')), '.', 1), '(peptides?|peps|lab)$', '')
    = regexp_replace(split_part(lower(s.domain), '.', 1), '(peptides?|peps|lab)$', '')
  AND (SELECT COUNT(*) FROM sites s2
       WHERE regexp_replace(split_part(lower(s2.domain), '.', 1), '(peptides?|peps|lab)$', '')
           = regexp_replace(split_part(lower(s.domain), '.', 1), '(peptides?|peps|lab)$', '')) = 1;

7The New 60-Second SOP When Any Domain Changes (For Junard, Carl & Store Ops)

Follow these 4 rules every time a domain is rotated so zero visitors, bookmarks, or orders are ever lost again.

  1. NEVER click "Delete Site" or "Add Site" in Deep2K for an existing city store! Instead, open the existing city store in Deep2K and click Rotate Domain (POST /api/sites/:id/rotate-domain), entering the new domain (e.g., oshawapeps.com).
  2. Keep the Same Tracker Script on the Shopify Store: Because rotate-domain keeps the exact same site_id, secret, and endpoint_path, the tracker script already inside theme.liquid on that Shopify store continues working immediately with zero gap!
  3. Set a Cloudflare 301 Redirect on the Old Domain (Whenever Possible): If the old domain is still in our Cloudflare account (not registry-suspended, e.g., steinbachpeptides.com, peptideschicago.com, torontopeptides.ca), add a Cloudflare Redirect Rule: https://old-domain.com/* → 301 Permanent Redirect → https://new-domain.com/$1 (Preserve Query String = ON) so bookmarked repeat buyers AND Google/TikTok ad clicks with ?utm_... or ?gclid=... redirect with their tracking parameters intact!
  4. Update Netgrid & Gerry's Ad Sheet the Same Day: Update Column A in the Master Sites Sheet (1oCb9B-Hc-xTKojTCszKtILoTOXiQtbybuF48LqTt6Qc) and update the blog's domain in Netgrid so SEO posts and Paid Ads never point to a retired domain.
