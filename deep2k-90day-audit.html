3Why Slow Buyers Lose Their Identity After 7 Days on iPhone/Safari (And How to Fix It)

If 60% of our Canadian customers browse on iPhones (Safari / TikTok in-app browser), localStorage.getItem('d2k_aid_v1') is NOT enough for a 90-day buying cycle.

The Two Browser Traps That Break 90-Day Tracking Today:
  1. Apple Safari ITP 7-Day Cap: On iOS Safari and macOS Safari, any localStorage entry (d2k_aid_v1) or JavaScript document.cookie (order_attribution_v2) is automatically wiped by Apple after 7 days if the user doesn't open that domain during those 7 days!
  2. TikTok / Instagram In-App WebView Isolation: When someone clicks a TikTok Ad, it opens inside TikTok's built-in browser (BytedanceWebview). If they click "Open in Safari" or type the URL into Safari 3 days later, Safari has a completely separate localStorage from TikTok's WebView!
The 3-Layer Fix for True 90–180 Day Persistence:
  1. Layer 1 — Server-Side HTTP Set-Cookie on First-Party Subdomains (t.store.com): When a store uses a First-Party Cloudflare Worker route (e.g. diagnostics.montrealpeptides.com), the Worker response sets an HTTP Set-Cookie: d2k_aid=<uuid>; Max-Age=15552000; Path=/; Domain=.montrealpeptides.com; SameSite=Lax; Secure.
  2. Layer 2 — Email / Phone Capture Stitching (form_submitted → customer_key): When a Day-1 ad visitor enters their email/phone in a "Get Lab COA PDF / 10% Off" popup, hash their email/phone into customer_key and save customer_key on journey_sessions! Then if they buy 45 days later on a different device or browser, recoverAttribution (same_customer) stitches the order back to their Day-1 ad click!
  3. Layer 3 — Increase COOKIE_DAYS = 180 & Sync Both localStorage + document.cookie: Store d2k_aid_v1 AND d2k_touch_v1 in both localStorage AND a 180-day document.cookie.

4The Missing Table for 90-Day Multi-Touch Journeys: `visitor_touchpoints`

Why `anonymous_visitors` (`first_*` and `last_*`) loses middle touchpoints, and why we need an append-only `visitor_touchpoints` ledger kept for 180+ days.

Look at what happens in `journeyStore.ts` today when a slow customer visits 4 times over 45 days:
  • Day 1: Clicks Gerry's TikTok Ad (`montreal_2026-10-01_ttvideo`) → `first_channel = Paid Social`, `last_non_direct_channel = Paid Social`.
  • Day 12: Searches Google and clicks Gerry's Google Search Ad (`montreal_2026-10-12_gbpc157`, keyword=`bpc 157 montreal`) → `last_non_direct_channel` is overwritten to `Paid Search`.
  • Day 25: Clicks a Google Business Profile (GMB) map listing → `last_non_direct_channel` is overwritten to `Business Profile` (**wiping out the Day 12 Google Search Ad from `anonymous_visitors`!**).
  • Day 40: Clicks Jerome's Promo Email (`montreal-free-ghk-cu`) and buys → `last_non_direct_channel` is overwritten to `Email`!
Because `journey_events` only stores raw pageviews (and gets pruned or is expensive to scan across 90 days), and `anonymous_visitors` only keeps `first_*` and `last_*`, **Touch #2 (the Day 12 Google Search Ad) and Touch #3 (the Day 25 GMB click) are overwritten on `anonymous_visitors` and `orders`!**

The Solution: Add `visitor_touchpoints` (1 Compact Row Per Marketing Touch, Kept 365 Days)

Every time a session starts with a non-Direct channel (or any tagged UTM/click ID), insert one lightweight row into `visitor_touchpoints`. Even 100,000 ad clicks is only ~15 MB in Postgres, so it can be kept for **365 days** and queried in milliseconds!

Ready-to-Paste SQL Query for the 90-Day Slow vs. Fast Buyer Report (/api/v1/analytics/sales)

-- Query: 90-Day Slow vs. Fast Customer Journey Breakdown per Acquisition Channel
WITH buyer_journeys AS (
  SELECT
    o.id AS order_id,
    o.site_id,
    COALESCE(o.first_channel, av.first_channel, '(unattributed)') AS intro_channel,
    COALESCE(o.last_non_direct_channel, av.last_non_direct_channel, o.first_channel, 'Direct') AS closing_channel,
    COALESCE(o.first_campaign, av.first_campaign) AS intro_campaign,
    o.currency,
    (o.amount - COALESCE(o.refunded_amount, 0))::float AS net_revenue,
    o.submitted_at,
    COALESCE(
      o.first_touch_at,
      av.first_seen_at,
      (SELECT MIN(vt.occurred_at) FROM visitor_touchpoints vt
       WHERE (vt.anonymous_id = o.anonymous_id OR (o.customer_key IS NOT NULL AND vt.customer_key = o.customer_key))
         AND vt.occurred_at <= o.submitted_at),
      o.submitted_at
    ) AS first_seen_at,
    COALESCE(
      (SELECT COUNT(DISTINCT js.id)::int FROM journey_sessions js
       WHERE js.anonymous_id = o.anonymous_id AND js.started_at <= o.submitted_at),
      1
    ) AS total_sessions
  FROM orders o
  LEFT JOIN anonymous_visitors av ON av.id = o.anonymous_id
  WHERE o.payment_status = 'paid'
    AND o.traffic_class IN ('human', 'likely_human')
    AND o.submitted_at >= now() - interval '90 days'
)
SELECT
  intro_channel,
  COUNT(*)::int AS total_paid_orders,
  ROUND(AVG(EXTRACT(epoch FROM (submitted_at - first_seen_at)) / 86400.0)::numeric, 1)::float AS avg_days_to_buy,
  ROUND(AVG(total_sessions)::numeric, 2)::float AS avg_sessions_to_buy,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at < interval '1 hour')::int AS fast_under_1h,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at >= interval '1 hour' AND submitted_at - first_seen_at < interval '24 hours')::int AS fast_1h_to_24h,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at >= interval '1 day' AND submitted_at - first_seen_at < interval '3 days')::int AS med_1d_to_3d,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at >= interval '3 days' AND submitted_at - first_seen_at < interval '7 days')::int AS med_3d_to_7d,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at >= interval '7 days' AND submitted_at - first_seen_at < interval '14 days')::int AS slow_7d_to_14d,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at >= interval '14 days' AND submitted_at - first_seen_at < interval '30 days')::int AS slow_14d_to_30d,
  COUNT(*) FILTER (WHERE submitted_at - first_seen_at >= interval '30 days')::int AS slow_31d_to_90d_plus
FROM buyer_journeys
GROUP BY 1
ORDER BY total_paid_orders DESC;

// Store d2k_aid_v1 and d2k_touch_v1 in BOTH localStorage AND a 180-day 1st-party cookie
var COOKIE_DAYS = 180;
function readCookie(name) {
  var m = document.cookie.match(new RegExp('(?:^|; )' + name + '=([^;]*)'));
  return m ? decodeURIComponent(m[1]) : null;
}
function writeCookie(name, value, days) {
  var d = new Date(Date.now() + (days || COOKIE_DAYS) * 86400000);
  var host = location.hostname.replace(/^www\./, '');
  document.cookie = name + '=' + encodeURIComponent(value) + ';expires=' + d.toUTCString() + ';path=/;SameSite=Lax';
  document.cookie = name + '=' + encodeURIComponent(value) + ';expires=' + d.toUTCString() + ';path=/;domain=.' + host + ';SameSite=Lax';
}
function read(key) {
  try {
    var ls = localStorage.getItem(key);
    if (ls) return JSON.parse(ls);
  } catch (_) {}
  try {
    var ck = readCookie(key);
    if (ck) {
      try { localStorage.setItem(key, ck); } catch (_) {}
      return JSON.parse(ck);
    }
  } catch (_) {}
  return null;
}
function write(key, value) {
  var raw = JSON.stringify(value);
  try { localStorage.setItem(key, raw); } catch (_) {}
  try { writeCookie(key, raw, COOKIE_DAYS); } catch (_) {}
}
